# System Design

This folder explains how the approved software requirements are realized by the platform's components, data, and interfaces.

- `architecture.md` — system boundary, software components, responsibilities, interfaces, data flow, and design decisions.
- `diagrams/` — editable system-analysis and software-design diagrams, plus a short description of each.

Keep the design consistent with `docs/requirements/`. The current project has no planned hardware; design for one responsive software experience rather than separate device-specific products. Put report-ready exported diagrams in `assets/diagrams/` and retain editable sources here.
