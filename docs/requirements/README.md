# Requirements Analysis

This folder defines what the system must do and how success will be checked. Keep requirements specific, testable, uniquely identified, and traceable to a stakeholder need or project objective.

- `requirements.md` — functional and non-functional requirements, priorities, and acceptance criteria.
- `use-cases.md` — actors, user goals, preconditions, normal flows, and alternatives.

Review requirements with the supervisor and intended users before treating them as approved. Link each requirement to relevant design elements and tests when those are created.
