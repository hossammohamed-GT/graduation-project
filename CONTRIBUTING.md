# Contribution Guidelines

## Before starting

- Check `TASK_ASSIGNMENTS.md` and agree on task ownership with the team.
- Read the `README.md` in the folder where you plan to work.
- Confirm project assumptions with the team before adding project-specific architecture or requirements.

## Files and changes

- Use English for repository documentation, file names, and code comments.
- Keep each document in its designated folder and use descriptive `kebab-case` file names.
- Keep diagrams editable when possible and export clean copies to `assets/` for reports.
- Do not commit passwords, API keys, personal contact information, private student records, or unapproved datasets.
- Update related documentation and tests when behavior or design changes.
- Avoid committing generated output, temporary files, or duplicate copies of the same asset.

## Review checklist

- Does the change match the approved project scope?
- Are claims, diagrams, and data sources traceable?
- Are the relevant tests or review steps recorded?
- Are placeholders clearly marked and owner/status information current?
