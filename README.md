# Intelligent Learning and Growth Platform

This repository is the shared workspace for planning, building, testing, and documenting the graduation project. The approved project title is **Intelligent Learning and Growth Platform**. The detailed problem, target users, technical scope, and architecture still need to be confirmed in the project charter before implementation begins.

## How to use this repository

1. Read `TASK_ASSIGNMENTS.md` and add an owner to each task after the team agrees on responsibilities.
2. Record the approved project scope, goals, and constraints in `docs/planning/project-charter.md`.
3. Keep research, requirements, design decisions, testing evidence, and report chapters in their dedicated folders.
4. Put source code in `src/`, hardware documentation in `hardware/`, datasets in `data/`, and report-ready media in `assets/`.
5. Update the relevant task status when a deliverable is reviewed and complete.

## Repository map

| Path | Purpose |
| --- | --- |
| `TASK_ASSIGNMENTS.md` | Project-specific task breakdown with deliverable checklists and blank owner fields. |
| `team/` | Team roster and notes about handling team information. |
| `docs/` | Planning, research, requirements, design notes, testing documents, final-report drafts, and presentation materials. |
| `src/` | Project implementation source code, organized by application, firmware, machine learning, and shared modules as applicable. |
| `hardware/` | Physical design, electronics, bill of materials, and prototype media. |
| `data/` | Dataset organization and documentation. Do not commit private, licensed, or very large data without approval. |
| `assets/` | Reusable diagrams, figures, and screenshots for reports and presentations. |
| `tests/` | Automated unit, integration, and system tests. |
| `tools/` | Reusable development, data, build, or documentation utilities. |

Every project directory contains a `README.md` describing what belongs there and how to organize it. Empty implementation areas are intentional until the team confirms the project architecture.

## Working conventions

- Use English for repository documentation, folder names, task descriptions, and code comments.
- Use clear, descriptive file names in `kebab-case`, such as `system-architecture.md`.
- Keep original evidence separate from edited, report-ready assets.
- Cite external material in the text and record its full bibliographic details in `docs/final-report/references/`.
- Do not commit credentials, private contact details, confidential datasets, or generated build output.
- Follow the institute's formatting guide when one is provided. This repository does not assume a font, margin size, or required export format.
